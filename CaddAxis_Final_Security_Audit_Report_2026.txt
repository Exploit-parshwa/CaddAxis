2. MEETING PLATFORM: OWNERSHIP & ISOLATION
--------------------------------------------------------------------------------

[MEETING HOSTING]
- [Check]: Self-Hosted Solution
  FAIL: The system currently relies on External Links (Zoom/Meet/Teams).
  Evidence: 'admin/online-classes/page.js' Line 202 shows <select> options for "Zoom", "Google Meet", "Teams".
  Evidence: Line 348 renders an anchor tag <a href={cls.meeting_link}> pointing to external URL.
  Note: No WebRTC or self-hosted media server (e.g., Jitsi/Janus/Mediasoup) implementation found in codebase.

- [Check]: Access Control
  FAIL: Meeting links are plain URLs exposed to the client.
  Evidence: Any user with the link can share it. No token-based join mechanism wrapping the external meeting.

4. SECURITY DEEP DIVE
--------------------------------------------------------------------------------

[IDOR VULNERABILITY]
- [Check]: Dashboard Access Control
  PASS: 'getStudentDashboard' enforces ID check via JWT.
  Evidence: 'actions.js' Line 547 decrypts 'student_session' cookie and IGNORES/OVERRIDES the 'requestedId' argument with 'payload.id'.
  Result: A student cannot iterate IDs to view other dashboards because the backend ignores the ID parameter.

[ADMIN SESSION SECURITY]
- [Check]: Server-Side Validation
  FAIL: 'authenticateAdmin' sets a cookie 'admin_session'='true'.
  Evidence: 'actions.js' Line 52 sets plain text cookie.
  Evidence: 'admin/layout.js' Line 117 logout just clears this cookie.
  Result: Any user who manually sets cookie 'admin_session=true' in DevTools can access Admin Panel. This is a critical security bypass.

[SQL INJECTION]
- [Check]: Parameterized Queries
  PASS: All database interactions use 'pool.query(sql, [params])'.
  Evidence: Consistent usage of '?' placeholders in 'actions.js'.

[XSS]
- [Check]: Output Encoding
  PASS: React automatically escapes content in JSX.
  Evidence: No usage of 'dangerouslySetInnerHTML' found in critical rendering paths.
